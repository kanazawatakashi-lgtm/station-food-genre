# 集計方法の整理（亀戸の試作から）

2026-10-02。亀戸駅で試した各手順の「手間」と「効果」を比べ、多くの駅に広げるときのやり方を決めるためのメモ。

## 亀戸で試した手順の費用対効果

| 手順 | 何をしたか | 効果（亀戸） | 手間 | 判断 |
|---|---|---|---|---|
| Overture 抽出 | S3 の GeoParquet を範囲指定で読む | 飲食 910 件。土台 | 小。23区全体（約14万件）でも1分程度 | **主データにする** |
| 店名ルール＋Overture 細分類 | 正規表現（チェーン名含む）と細分類の対応表 | 判定率 81.8%（23区では 73.4%） | 小。一瞬で終わる。ルールは使い回せる | **主手段にする** |
| Claude の店名判定 | 決まらない店を店名・分類・住所から判定 | +53 件（約6%）。高・中のみ採用 | 小。API で一括処理できる | **使う**（比較対象側にも同じく掛ける） |
| 重複の除去 | 50m 以内・店名一致・同ジャンル | 約1%減 | 小 | **使う**（安いので） |
| OSM のタグ | Overpass で取り、店名と距離で照合 | 判定不能を埋めたのは +5 件だけ | 中。ローカル実行が必要 | **補完には使わない。精度確認に使う**（一致率 89%） |
| JFF（OpenPOI 経由） | bbox 分割で取り、名寄せ | +95 店（約10%） | 大。ローカル実行、名寄せの調整、飲食店以外の除外 | **主集計には入れない**（下記の理由） |
| 商用 API（ホットペッパー、Yahoo、ぐるなび、Google） | — | — | — | **使わない**。規約で保存・二次利用が制限されている。ぐるなびは無料提供終了 |

## 分かったこと

1. **ジャンル判定の精度はおよそ9割。** 店名ルールの結果は、Overture 細分類との一致が 88%、OSM のタグとの一致が 89%（それぞれ独立に確認）
2. **店の網羅に穴がある。** OSM にあって Overture に無い店が、OSM の店の2割前後ある。漏れはラーメン店・居酒屋に多い
3. **JFF は穴を埋めきれず、地域でむらがある。** 江東区は区の許可一覧が入っているが、墨田区は国の電子申請分だけ。
   亀戸 1km 圏でも JFF の飲食店は約250件で、OSM にしかない店35件のうち JFF で拾えたのは2件。
   JFF を駅ごとに足すと、**区によって足される量が違うので駅どうしの比較がゆがむ**
4. **比較はデータの作り方をそろえることが一番大事。** 駅側だけに追加データや追加の判定を入れると、構成比の差が
   「街の違い」なのか「データの違い」なのか分からなくなる。Overture の漏れも、全駅で同じように漏れるなら比較への
   影響は小さい
5. **居酒屋とバーの境界は分類方法で動く。** 酒場系（居酒屋＋バー＋スナック）をまとめると亀戸の LQ は 1.04 で
   平均並みだが、内訳は 1.59 と 0.79 に割れる。内訳は比べず、まとめて扱うのが安全
6. **件数の少ないジャンルは LQ が不安定。** 1駅10件未満のジャンルは1〜2店で LQ が大きく動く

## 多くの駅に広げるときのやり方

**方針: 「都内全域を一度に処理し、駅ごとに切り出す」。駅ごとに取得・判定しない。**

```
1. Overture: 東京都全域の飲食 POI を1回で取得             （クラウドで可）
2. 全件を一度に判定: 店名ルール → Overture 細分類
3. 決まらない店名だけを重複なしで Claude API に一括で送る     （Batch API で半額）
4. 重複の除去を全域で1回
5. 駅一覧: 国土数値情報 S12（座標・乗降客数）。同名駅は事業者をまたいで合算  （取得だけローカル）
6. 駅ごとに半径1km の店を切り出す（重なりは両方に数える）
7. 比較対象（都全域または23区）の構成比も同じ表から出す → 特化係数（LQ）、乗降客1万人あたり店舗数
8. 精度確認: いくつかの駅だけ OSM と照合し、一致率と漏れ率を記録                （取得だけローカル）
```

この形にする理由:

- **判定が1回で済む。** 駅の圏は重なるので、駅ごとに判定すると同じ店を何度も判定することになる
- **比較対象と駅側の判定方法が自動的にそろう。** 今の亀戸では Claude 判定を比較対象側に掛けられず、LQ をルールだけで
  計算していた。全域を一度に判定すれば、Claude 判定も含めた結果で LQ を出せる
- **Claude に送る量が減る。** チェーン店や同名店は1回の判定で済む。23区の判定不能は約3.7万件。店名の重複を除けば
  さらに減る。費用は Batch API で数十ドル程度の見込み（モデルと件数で変わる。実行前に件数で見積もる）
- **ローカルでの作業が S12 の取得（と精度確認用の OSM）だけになる。** Overture はクラウド環境から取れる

## 表の出し方

- ジャンルは今の37区分で判定し、**集計表では件数の少ないものをまとめる**（例: 酒場系＝居酒屋＋バー＋スナック・パブ、
  各国料理をまとめる など）。まとめ方は全駅の件数分布を見てから決める
- 各駅の表には **判定率と、判定不能の件数** を必ず載せる
- LQ は **件数10件以上のジャンルだけ** 示し、それ以外は「件数少」とする
- 「Overture は店の約2割を取りこぼしている（OSM との照合での目安）」ことを注記する。ラーメン店・居酒屋は少なめに出ている

## JFF の扱い

主集計には入れない。使うとしたら次のどちらか。

- **区の許可一覧が入っている区だけで、補正の大きさを見る**（江東区など）。全駅の比較には使わない
- 都が全区分の営業許可データをまとめて公開していないか確認し、そろっているなら主データに加える（未確認）

## まだ決めていないこと

- 対象駅を絞る乗降客数の閾値
- 比較対象を23区にするか都全域にするか（多摩地域の駅を入れるなら都全域）
- 集計表でのジャンルのまとめ方
- 出力の形（スプレッドシート、ダッシュボードなど）

## モデル比較の結果（2026-10-03、`data/areas/model_compare.csv`）

答え合わせ用 300 店（Overture の料理系細分類を正解として伏せ、店名と住所だけで判定）での確信度別の正解率:

| | 高 | 中 | 低 |
|---|---|---|---|
| Opus 5.5 | 79 件・78%（両モデルが一致して正解と違う店を正解側の誤りとみなすと 89%） | 88 件・64%（同 76%） | 60 件・22% |
| Haiku 4.5 | 111 件・76%（同 85%） | 97 件・40%（同 55%） | 29 件・17% |

- 正解の数はほぼ同じ（Opus 118、Haiku 123）だが、採用した中での誤りは Opus 49、Haiku 85。Haiku は「中」の質が低い
- Opus の「高」での誤りの多くは、正解側（Overture）の分類がおかしいか、ジャンルの境界にあるもの
  （銀座コージーコーナー: 正解パン→判定スイーツ、さくら水産: 正解海鮮→判定居酒屋、パティスリー: 正解パン→判定スイーツ など）
- 誤りの多い組: 海鮮・魚料理↔居酒屋、パン↔スイーツ・和菓子、韓国料理↔焼肉・ホルモン、ステーキ・ハンバーグ↔ハンバーガー。
  集計表でジャンルをまとめるときの候補
- 費用（実測から換算、Batch API）: Opus 約15ドル、Haiku 約3ドル
- **判断: Opus 5.5 を使う。** 採用する確信度（高だけか、高・中か）は判定後に決められる（同じ結果から切り替えるだけ）ので、
  本番は Opus で一度だけ実行し、高だけ／高・中の両方で LQ を出して差を見る

## 集計用のジャンル体系（2026-10-03）

判定は細かい37ジャンルのまま行い、集計時に `scripts/genre_groups.py` で大分類5つ・中分類25に付け替える。
大分類だけ分かる店（Overture で japanese_restaurant とだけ分類された店など）は中分類を「不明」にする。
ユーザーの指定: ステーキ・ハンバーグは洋食に含める／ファミレスは独立／とんかつと串かつは分ける。
パンとスイーツは分ける（取り違えが多い組み合わせなので、この2つの比較は幅を持って読む）。
惣菜・弁当は集計に入れる（ユーザー確認済み）。居酒屋・バー・スナックの統合は、たたき台のまま（未確認）。

## 店数の確からしさ（2026-10-03）

23区の Overture 飲食 POI（重複除去後 119,748）は、経済センサス2021の区部の飲食店 54,465 事業所の約2.2倍。
閉店済みの残り、表記違いの重複、パン・菓子・惣菜の小売（センサスでは小売業）を含むため。一方で OSM との照合では
2割前後の店が Overture に無い。件数そのものは当てにせず、構成比・特化係数で比べる前提は変わらない。

**confidence 0.5 未満を外す**（`classify_area.py` の MIN_CONFIDENCE）:
- 亀戸で OSM・JFF と照合した、確認できた店の割合: 0.3 未満 0%（34店）／0.3〜0.7 約6%／0.7〜0.9 約11%／0.9 以上 22%
  （OSM・JFF とも一部の店しか載っていないので割合は全体に低い。帯の間の差を見る）
- 23区で 0.5 未満・0.7 未満を外してもジャンル構成比はどれも 0.4 ポイント以内しか変わらない
- 0.9 以上に絞るとチェーンに偏る（ファミレス 1.51 倍、ハンバーガー 1.33 倍、スナック 0.73 倍、惣菜 0.69 倍）ので使わない
- 結果: 108,658 店（11,266 店を除外）。Claude に送る店名は 32,196 種類

## 区ごとの経済センサスとの比較（2026-10-03、`data/census/ward_compare.csv`）

経済センサス2021 第31-13表（`data/census/b2_031_13.xlsx`、ユーザーがローカルで取得）の「76 飲食店」事業所数と、
Overture（confidence 0.5 以上、重複除去後、パン・スイーツ・惣菜を除く）の区ごとの件数を比べた。

- 23区合計: センサス 54,312 ／ Overture 102,511（1.89 倍）
- **倍率が区によって大きく違う**: 千代田 2.58・港 2.50・目黒 2.30・渋谷 2.25 … 練馬 1.33・板橋 1.32・葛飾 1.23・足立 1.21
- 都心・繁華街ほど Overture が多めに出る。閉店の入れ替わりが激しい、ビル内の店や観光客向けの店が地図サービスに
  多く登録される、などが考えられるが、原因は切り分けられていない
- 影響: 店の数（乗降客1万人あたり店舗数など）は都心の駅ほど過大になる → 区ごとの倍率で割り戻した「センサス換算」で比べる。
  構成比・特化係数も、多めに出ている分が特定のジャンル（カフェ・バーなど）に偏っていれば、都心と郊外の比較がゆがむ。
  センサスの小分類（そば・うどん、すし、酒場、バー、喫茶店など）の区別の数と突き合わせれば確かめられる

## 駅の切り出しとセンサス補正（2026-10-03、Claude 判定前に準備）

**駅の切り出し**（`scripts/station_table.py`）: 23区の判定結果（`tokyo23_genre.parquet` の重複をまとめた代表の行）から
半径1km の店を数える。比較対象は23区全体の同じ表なので、駅と比較対象で判定方法・重複のまとめ方が揃う。
構成比の分母は、大分類なら大分類が分かる店、中分類なら中分類が分かる店だけ。

**センサス補正**（`scripts/census.py`）: 店1件を「区×センサス小分類の重み」件として数える。
重み = センサスの事業所数 ÷ Overture の推定件数。推定件数は中分類が分かる店の件数を
（飲食店全体 ÷ 中分類が分かる店）倍したもの（中分類不明の店が同じ割合で散らばっているとみなす）。
中分類不明の店とパン・スイーツ・惣菜には、その区の飲食店全体の重みを使う。

Claude 判定前の重み（暫定）: 飲食店全体 0.38（千代田）〜0.82（足立）。小分類では喫茶店 0.19〜0.44、
酒場 0.86〜1.96、バー等 0.16〜1.49 と区による差が大きい。

亀戸（判定前・暫定）で補正の有無を比べると、LQ は多くの中分類で 0.1〜0.3 ほど 1 に近づく
（居酒屋 1.53→1.36、ラーメン 1.31→1.09、焼き鳥 1.52→1.31）。逆に離れるものもある（洋食 0.92→1.15、ハンバーガー 1.61→1.75）。補正なしの LQ は「Overture が郊外で少なめに拾う
ジャンル」を高く出していた分がある。どちらを採るかは Claude 判定後に決める。

**乗降客数**（`scripts/s12_stations.py`）: S12 のグループコードで乗換駅をまとめ、乗降客数は事業者ごとの最大値を合計する
（同じ事業者の同じ駅が路線ごとに同じ数字で載ることがあるため）。円が23区の外にはみ出す駅は `near_edge=1`
（外側の店はデータに無い）。

## 23区の全駅（2026-10-04、Claude 判定前・暫定）

S12-25（国土数値情報 駅別乗降客数、2024年の値 `S12_061`）から23区内 490 駅（`data/stations.csv`）。
- 乗降客数なし3駅（とうきょうスカイツリー、上野動物園東園・西園）
- 円が23区の外にはみ出す駅（near_edge）: 半径1000m 64、500m 22、300m 14。お台場など海に面した駅も含む
- 同じ駅名でもグループコードが違う駅（東京駅の京葉線など）は 500m 以内ならまとめた。
  「新宿西口」「新宿三丁目」のように駅名が違う駅は別の駅のまま
- 乗降客数の多い順: 渋谷 290万、新宿 271万、池袋 236万、北千住 143万、東京 126万。亀戸 13.6万（JR 11.0万＋東武 2.6万）

`data/stations/tokyo23_r<半径>_lq_mid.csv` が駅ごとの一覧（店数、センサス補正後の店数、乗降客1万人あたり店舗数、中分類 LQ）。

**乗降客1万人あたり店舗数は、そのままでは駅の比較に使いにくい。** 1km 圏は隣の駅と大きく重なるので、
銀座・日本橋周辺の乗降客3〜4万人の駅（銀座一丁目・宝町・新日本橋など）が、周りの大きな駅の店を数えて
1万人あたり 450〜950 店になる。逆に渋谷・池袋・北千住は乗降客が多すぎて 5〜7 店。亀戸は 35.5 店
（乗降客3万人以上・23区内に収まる 233 駅中 145 位）。使い方の案:
- 乗降客の基準で駅を絞る（ユーザーが後で決める）
- 円の重なりを考えるなら、乗降客を近い駅どうしで分け合う、または周辺駅の乗降客を距離で重み付けして足した「圏の乗降客」で割る
