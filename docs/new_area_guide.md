# ほかの地域で同じサービスを作る手順

東京23区版と同じ「飲食出店ナビ」を、ほかの地域（例: 大阪市、名古屋市、横浜市、福岡市）で作るときの手順（2026-10-05 作成）。
使っているデータはすべて全国で同じ形で取れるもの（Overture、国土数値情報、e-Stat、位置参照情報）なので、
データの面では同じ作り方ができる。ただし今のコードは東京23区に合わせて決め打ちしている箇所が多いので、
**先にコードを「地域の設定」で切り替えられる形に直す**（3.）のがいちばん大きな作業になる。

## 1. 決めること（ユーザー）

| 項目 | 決めること | 23区版での決め方 |
|---|---|---|
| 対象地域 | どの市区町村をまとめて1つの地域にするか | 東京23区（23の特別区） |
| 比較の基準 | 平均比の分母になる「地域全体」 | 対象地域全体（23区全体）。ほかの地域でも「対象地域全体」にする（地域ごとに基準が違うので、地域をまたいで平均比を比べない） |
| 区の単位 | 補正（経済センサス）と地図の境界に使う単位 | 区。政令市なら行政区、それ以外なら市町村 |
| 駅の範囲 | どの駅を載せるか | 駅が23区内にあるもの（乗降客数が公表されている駅） |
| 名前 | サービスの名前 | 飲食出店ナビ・東京23区版 → 例「飲食出店ナビ・大阪市版」 |
| 公開の形 | 地域ごとに別のページにするか、1つのページで切り替えるか | 23区版だけで 6.6MB あるので、**地域ごとに別のページ**をすすめる |

## 2. 集めるデータ（ユーザーがダウンロードして push。push の手順は `docs/update_guide.md` の 2.）

| データ | 取得先 | 地域ごとに選ぶもの | 置き場所 |
|---|---|---|---|
| 行政区域 N03 | https://nlftp.mlit.go.jp/ksj/ →「政策区域」→「行政区域」 | 対象の都道府県（隣の都道府県にまたがるなら両方） | `data/ksj/` |
| 鉄道 N02 | 同上 →「交通」→「鉄道」 | 全国（23区版で取ったものをそのまま使える） | `data/ksj/`（取得済み） |
| 駅別乗降客数 S12 | 同上 →「交通」→「駅別乗降客数」 | 全国（取得済みの S12-25 をそのまま使える） | `data/s12/`（取得済み） |
| 位置参照情報 街区レベル | https://nlftp.mlit.go.jp/isj/ | 対象の都道府県 | `data/isj/<都道府県コード>_<年>.csv` |
| 国勢調査 地域メッシュ（250m） | e-Stat →「地図」→「統計データダウンロード」→ 国勢調査 2020 | 対象地域を含む **1次メッシュ**（例: 大阪市 5235、名古屋市 5236、福岡市 5030。範囲の境目にかかるなら複数） | `data/mesh/` |
| 経済センサス 地域メッシュ（500m） | 同上 → 経済センサス‐活動調査 2021 | 同じ1次メッシュ | `data/mesh/` |
| 経済センサス 市区町村別・産業小分類別の事業所数 | e-Stat → 経済センサス‐活動調査 2021 → 第9-1A表 | 取り直し不要（23区版の `data/census/b1_009_1a.xlsx` に全国の市区町村が入っていることを確認済み） | `data/census/` |

Overture（店舗）は Claude がこの作業環境から取る。

1次メッシュの番号は「緯度×1.5 の整数部」と「経度−100 の整数部」を並べたもの（例: 大阪市役所 北緯34.69°・東経135.50° → 52・35 → 5235）。

利用条件は全国同じ（`docs/licenses.md`）。新しく取るファイルのデータページでも、利用規約の版を確かめる。

## 3. コードを地域の設定で切り替えられるようにする（Claude、最初に一度だけ）

今のコードで東京23区に決め打ちしている箇所。地域ごとの設定ファイル（例: `areas/tokyo23.json`、`areas/osaka.json`）に
まとめ、各スクリプトが `--area` で読む形に直す。直したあと、23区版を作り直して `docs/app.html` が変わらないことを確かめてから、
新しい地域に進む。

| ファイル | 決め打ちしている内容 | 設定にするもの |
|---|---|---|
| `ksj.py` | N03 のファイル名、区のコード（13101〜13123）、「23区がそろわない」の確認、出力ファイル名 | N03 のファイル、対象の市区町村コードの一覧 |
| `census.py` | `WARD_EN`（区の日本語名と英語名）、表の読み取り（「131」で始まる行、23区） | 市区町村コードと名前の一覧（英語名はやめて市区町村コードで持つ） |
| `fetch_overture_area.py` | 「tokyo23 だけ対応」 | 地域名（境界は `ksj.load_wards` から） |
| `s12_stations.py`・`mesh_stats.py` | `tokyo23_wards.parquet`、出力ファイル名 | 地域名 |
| `station_table.py` | 端の判定の緯度（35.7） | 地域の中心の緯度 |
| `svgmap.py` | 地図の範囲と投影（`LAT0`・`MIN_LNG`・`MAX_LAT`）、`build_app.py` の地図の右下（139.925, 35.515） | 地域の範囲（境界から自動で計算できる） |
| `build_app.py` | `tokyo23_*` のファイル名、位置参照情報 `13_*.csv`、面積計算の緯度、住所の索引の基準（緯度35・経度139） | 地域名・都道府県コード・基準の緯度経度 |
| `app_template.html` | 画面の「23区」（22か所）、名前、初期表示の駅（渋谷・成城学園前）、住所・座標の例と初期値、住所の頭の「東京都」、座標の範囲の確認（北緯35.4〜35.95、東経139.4〜140.1）、住所の索引の基準（35・139）、ジャンル別の初期表示 | 地域名・都道府県名・初期の駅・例の住所と座標・範囲 |
| `ksj.py` の路線名 | 事業者名の短縮（東京メトロなど）、通称（りんかい線など）、地下鉄の判定（東京地下鉄・都営・横浜市営） | 地域の事業者を足す（大阪メトロ、名古屋市営地下鉄、福岡市地下鉄など。**地下鉄の判定は事業者ごとに書く必要がある**） |
| `genre_rules.py` | 店名ルールのチェーン名 | 地域のチェーン（関西・中部・九州のチェーン）を足す。足さなくても AI 判定で補えるが、判定の数と費用が増える |
| `dedupe.py` | 重複をまとめるときに外す駅名（亀戸・錦糸町など） | 一般的な形（「○○店」を外す）に直す |
| `classify_area_with_claude.py` | 送る文の「東京23区内で同じ店名の店の数」 | 地域名 |
| `docs/disclosures.md` の数字 | 23区での比較の数字（地図サービスの件数がセンサスの約1.9倍 など） | 地域ごとに出し直す |

## 4. 作る手順（データがそろってから）

1. 境界と店: `python scripts/fetch_overture_area.py <地域>`（境界は N03 から作り、その中の飲食 POI を取る）
2. ジャンル判定: `python scripts/classify_area.py <地域>`
3. AI 判定（ユーザーが手元で実行。`docs/update_guide.md` の 4.）: すでに判定済みの店名（23区版の `tokyo23_claude.csv`）と
   同じ店名は流用できるようにしてから送る（全国チェーンは判定済みのことが多く、送る数が減る）
4. 反映: `python scripts/classify_area.py <地域>`
5. 補正の重み: `python scripts/census.py <地域>`
6. 駅: `python scripts/s12_stations.py data/s12/S12-25_NumberOfPassengers.geojson --passengers S12_061 --area <地域>`
7. 駅ごとの集計: `python scripts/station_table.py <地域> --stations data/stations_<地域>.csv --radius 250/500/1000`（3回）
8. 人口・働く人: `python scripts/mesh_stats.py ...`（README のコマンドの地域版。1次メッシュのファイルを全部渡す）
9. 画面: `python scripts/build_app.py --area <地域>` → `docs/app_<地域>.html`
10. 公開: 新しい公開ページとして出す（23区版とは別の URL）

（3. の作り直しのあと、コマンドの形は少し変わる。上は直したあとの形の見込み）

## 5. 確かめること（公開の前）

- [ ] 地図: 境界・線路・駅の位置がずれていないか。路線の色（JR・私鉄・地下鉄）の分け方が正しいか
- [ ] 店の数: 区（市町村）ごとに、地図サービスの件数と経済センサスの事業所数の比を出す（23区は約1.9倍、都心ほど多い）。
      極端な区がないか
- [ ] 判定率: 中分類まで判定できた店の割合（23区は約83%）。大きく下がるなら、店名ルールに地域のチェーンを足す
- [ ] 乗降客数: 上位の駅が実感と合うか。乗換駅のまとめ方（同じ駅名で500m以内）がうまくいっているか
- [ ] 端の駅: 地域の外（隣の市や海）にかかる駅に注意が出るか
- [ ] 住所検索: 例の住所と、いくつかの住所で引けるか
- [ ] 同じ名前の別の駅: 路線名が添えられて区別できているか（`build_app.py` が自動で付ける。路線名の呼び方は `ksj.py` の短縮・通称）
- [ ] 画面の文言: 「23区」が残っていないか、例の駅・住所・座標がその地域のものか
- [ ] 出典・留意点・`docs/disclosures.md`: 地域名、データの版、地域ごとの数字（判定率・補正の例）
- [ ] スマホの幅で崩れないか

## 6. 規模の目安

| 作業 | 23区版での実績・見込み |
|---|---|
| コードの地域対応（3.） | 最初の1回だけ。Claude の作業で半日〜1日程度の見込み |
| データのダウンロード（2.） | ユーザーの作業で1時間程度 |
| AI 判定 | 23区版は 32,196 種類の店名。地域の店の数に比例し、23区版で判定済みの店名は送らずに済む |
| 公開ページの大きさ | 23区版（店 107,121 件・駅 488）で 6.6MB。店の数に比例する |

## 7. 注意

- 平均比の基準は地域ごとに違う。「大阪市版の 1.5倍」と「23区版の 1.5倍」は、それぞれの地域の中での比較なので、地域をまたいで比べない
- 地方都市は鉄道より車の利用が多く、「駅まわり」だけでは店の立地を捉えきれない。駅を使わない地点分析の比重が上がる
- 経済センサスの補正は区（市町村）の単位なので、市町村が大きい地域ほど補正が粗くなる
- 乗降客数が公表されていない駅（23区では3駅）は載らない。地方の小さい駅ほど公表されていないことがある
